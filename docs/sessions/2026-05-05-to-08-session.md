## Work threads

### 1. mindcockpit-ai/cognitive-core#285 — silent-failure hardening

**Bug:** `.github/workflows/project-board-automation.yml` had 6 sites using `gh project item-list ... 2>&1 | tr -d '\000-\037'`. With pipefail off (or with `tr` always exiting 0), `gh` failures were masked; gh's stderr contaminated `$ITEMS` via `2>&1`; downstream `jq` either crashed (`Invalid numeric literal at line 1, column 8` on PR open) or quietly returned empty results (`Reconciliation complete: 0 issues fixed` on schedule reconcile).

**Fix (PR mindcockpit-ai/cognitive-core#286, commits c763c76 + 7a0a4e4):** three-part hardening applied to all 7 affected `run:` blocks (the issue body listed 6, but board-reconcile at line 395 also needed it):
- `set -euo pipefail` per block (CLAUDE.md mandate; default-bash adds `-e -o pipefail` but not `-u`).
- Drop `2>&1` so gh errors land on stderr, visible in CI logs, instead of contaminating `$ITEMS`.
- `jq -e 'type=="object" and has("items") and (.items|type=="array")'` shape probe; on failure emit `::warning::` with first-80-chars preview piped through `tr -c '[:print:]' '?'` to neutralize newline + `::error::` annotation injection.

**Peer review** spawned 3 specialists in parallel (code-standards, security, architect). Findings consolidated:
- F1 MAJOR: `set -o pipefail` should be `set -euo pipefail` (CLAUDE.md mandate). Applied.
- F2 MAJOR: `issue-opened` block missed in initial pass (no item-list pipe but coverage gap). Applied.
- F3 NIT: 80-char preview vulnerable to GitHub-annotation injection if gh response contains newline + `::error::`. Applied (`tr -c` sanitizer).
- M2 (architect): `jq empty` only validates parseability — `{"foo":"bar"}` would have re-surfaced the original silent-zero-progress bug. Replaced with shape probe. Verified with 8 cases.

### 2. mindcockpit-ai/cognitive-core#287 — board-reconcile scalability discovered during mindcockpit-ai/cognitive-core#285 verification

**Bug:** `board-reconcile` iterated over active board items doing one `gh issue view <N> --json state` REST call each. Today's 112-active-item board (76 Backlog + 13 Roadmap + 11 Todo + 6 In Progress + 4 null + 2 To Be Tested) hit GitHub's secondary rate limit at ~80 sequential calls and the job was cancelled at the exact 15-min step boundary.

Pre-mindcockpit-ai/cognitive-core#286 the silent-failure bug masked this as `success: 0 issues fixed` with a cryptic `jq: parse error` in the log (mindcockpit-ai/cognitive-core's 2026-05-05 08:18Z run). Post-mindcockpit-ai/cognitive-core#286 the cancellation was overt and diagnosable — exactly what the hardening was designed to enable.

**Fix (PR mindcockpit-ai/cognitive-core#288, commit 779fef5):** replace the per-issue REST loop with aliased GraphQL queries batched in groups of 100:

```graphql
query { repository(owner: "...", name: "...") {
  i287: issue(number: 287) { state }
  i286: issue(number: 286) { state }
  ...
} }
```

Local benchmark on the live 112-item board: **1 second** end-to-end versus the 15-min timeout. 2 GraphQL round-trips replace 112 sequential REST calls. Existing per-stale-item mutation path is unchanged.

## Lessons captured

- **Default GitHub Actions `bash` shell sets `-e -o pipefail` but NOT `-u`.** For CLAUDE.md compliance and unbound-variable safety, prefer explicit `set -euo pipefail` per `run:` block.
- **`2>&1` into a captured variable is a footgun** — gh's stderr ends up in `$ITEMS` and contaminates downstream parsers. Always keep stderr on stderr unless deliberately interleaving.
- **`jq empty` is too permissive** for shape-validating API responses. Use `jq -e 'type == "object" and has(...) and (.field|type=="array")'` to catch wrong-shape JSON.
- **Aliased GraphQL queries** are the right pattern for bulk lookups by primary key when you have N IDs. Up to ~100 aliases per query under default cost limits; batch larger sets.
- **CCR sandbox is minimal** — does NOT ship `gh` CLI. Future scheduled routines that need GitHub access must use `curl` + GitHub App installation token, not `gh`.
- **`gh secret set` whitespace gotcha** — always pipe via stdin with `printf '%s' "$TOKEN"` (no `--body`, no trailing newline). A trailing `\n` produces HTTP 401 Bad credentials with no diagnostic in the log.
- **GitHub Actions schedule cron** is consistently 2-2.5h late on this org's free tier. The 06:00 UTC cron fires between 07:47Z and 08:41Z empirically.
